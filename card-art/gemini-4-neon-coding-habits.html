CENTRAL THESIS

过去为旧模型设计的繁琐护栏、重复规则与冗长上下文，如今反而会引发指令冲突并拖慢新模型。

模型推理能力跃升后，开发者的核心工作不再是“事无巨细地写死禁令”，而是通过清晰的接口、按需读取的技能树与精准的视觉/交接机制，持续降低上下文噪声。

HABIT 01 · JUDGMENT OVER RIGID BANS

移除严格禁令，改用判断提示

  • • 删掉系统指令中冗长的代码风格禁令（极易与当前需求冲突，导致模型浪费思考 token 甚至盲从旧规则），改为“匹配周边代码库风格、命名和注释密度”等简洁判断提示。
  • • 将用户级 GEMINI.md 精简到一屏以内，只保留通用安全底线（如推送或部署前展示 diff、核实一手来源、长任务设进度提醒）和回复格式偏好。
HABIT 02 · SINGLE-SOURCE INTERFACE

在清晰的接口中只声明一次工具规则

  • • 删除系统指令中重复的工具使用说明以及 few-shot 示例——旧示例反而会诱导模型在边缘场景下照搬错误的参数结构。
  • • 规则只写一遍：自定义 Agent 通过工具的 JSON Schema（明确类型、枚举值、必填项）直接约束；日常编码代理依靠清晰的 CLI 参数、严格选项与直接报错信息。同时精简重叠工具，将长日志写入文件而非塞进上下文。
HABIT 03 · ON-DEMAND SKILLS

按需加载技能，淘汰臃肿项目文档

  • • 删掉臃肿的项目级 AGENTS.md / GEMINI.md（目录结构模型可自行读取，静态记录极易过时），仅保留简短项目说明与无法从代码推断的真实“坑点”（如非标准测试命令、共享类型文件位置）。
  • • 将 UI 规范、API 审查、内部 CLI 指南拆成轻量级 skills，在索引中用一句话描述，较长技能拆分为关联文件树。Gemini 4 Neon 能可靠按需读取，大幅压低首轮无效上下文与试错成本。
HABIT 04 · MULTIMODAL VERIFICATION

用图片和视频进行引导与视觉验收

  • • 涉及 UI 布局、数据图表或交互动效时，直接投喂参考截图或短录屏，取代大段低效的文字与 CSS 描述。
  • • 要求 Agent 在任务结束前执行视觉自检：实际渲染页面、图表或视频帧，直接打开生成的 PNG 或片段核查，捕获文字日志无法暴露的文本截断、标签换行与对齐错位。
HABIT 05 · HANDOFF OVER COMPACTION

用上下文交接代替中途自动压缩

  • • 即便拥有 1M 上下文窗口，长会话依然会变噪变慢；而中途自动压缩（Compaction）会破坏 prompt 缓存、丢失行级细节，迫使模型反复重读文件。
  • • 在任务切换节点让 Agent 输出简短交接文件（记录目标、已验证决策与确切文件路径），据此开启新会话；并行第二条任务线时直接 fork 会话。若自建循环保留压缩兜底，阈值建议设在 500k token 左右，并在摘要中固定活跃路径与既定决策。
